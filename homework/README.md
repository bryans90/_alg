# 計算 $2^n$ 的方法與執行效率比較分析

本專案實作並測試了四種不同的計算 $2^n$ 的演算法，從基礎的內建運算子到遞迴以及動態規劃（Memoization）優化技術，分析其執行時間與時間複雜度（Time Complexity）。

---

## 演算法實作說明

### 1. 方法 1：直接次方運算 (Built-in Operator)
- **原理**：直接利用 Python 的內建運算子 `2**n`。
- **時間複雜度**：$\mathcal{O}(1)$ 或 $\mathcal{O}(\log n)$（底層優化位元運算）。
- **說明**：這是效率最高且語意最清晰的方法。

```python
def power2n_1(n):
    return 2**n
```

---

### 2. 方法 2a：雙重遞迴 (Tree Recursion)
- **原理**：利用 $2^n = 2^{n-1} + 2^{n-1}$ 展開成樹狀結構。
- **時間複雜度**：$\mathcal{O}(2^n)$
- **說明**：每次呼叫都衍生出兩個子問題，且無任何快取機制。隨著 $n$ 增加，計算量呈指數型爆發，當 $n > 30$ 時會有極度明顯的卡頓現象。

```python
def power2n_2a(n):
    if n == 0:
        return 1
    return power2n_2a(n - 1) + power2n_2a(n - 1)
```

---

### 3. 方法 2b：單線遞迴 (Linear Recursion)
- **原理**：利用 $2^n = 2 \times 2^{n-1}$ 遞迴。
- **時間複雜度**：$\mathcal{O}(n)$
- **說明**：雖然是遞迴，但每次呼叫僅進行一次子問題求解，總共只遞迴 $n$ 次，效率遠優於方法 2a。

```python
def power2n_2b(n):
    if n == 0:
        return 1
    return 2 * power2n_2b(n - 1)
```

---

### 4. 方法 3：遞迴 + 查表 (Memoization / Dynamic Programming)
- **原理**：保留方法 2a 的 $2^{n-1} + 2^{n-1}$ 結構，但引入哈希表（Dictionary）來記錄已計算過的結果。
- **時間複雜度**：$\mathcal{O}(n)$
- **說明**：第一次計算出 $2^{n-1}$ 的結果後便直接寫入快取，第二次對 $2^{n-1}$ 的請求直接回傳紀錄，成功避免了重覆計算，將時間複雜度從指數級 $\mathcal{O}(2^n)$ 降至線性級 $\mathcal{O}(n)$。

```python
memo = {}


def power2n_3(n):
    if n in memo:
        return memo[n]
    if n == 0:
        return 1
    memo[n] = power2n_3(n - 1) + power2n_3(n - 1)
    return memo[n]
```

---

## 執行效能比較 (以 $N = 25$ 為例)

| 方法 | 演算法類型 | 時間複雜度 | 估算執行時間 ($N=25$) | 備註 |
| :--- | :--- | :--- | :--- | :--- |
| **方法 1** | 底層位元 / 內建 | $\mathcal{O}(1)$ | $< 0.000001$ 秒 | 最快，無額外開銷 |
| **方法 2a** | 雙重遞迴 | $\mathcal{O}(2^n)$ | $\approx 0.8 \sim 1.5$ 秒 | 最慢，大量重複計算 |
| **方法 2b** | 單線遞迴 | $\mathcal{O}(n)$ | $< 0.000010$ 秒 | 效能優良 |
| **方法 3** | 遞迴 + 查表 | $\mathcal{O}(n)$ | $< 0.000015$ 秒 | 大幅優化雙重遞迴 |

---

## 結論

1. **重複計算是效能殺手**：方法 2a 雖然程式寫法直覺，但因為沒紀錄算過的子問題，導致呼叫次數為 $2^{n+1}-1$ 次，效能極差。
2. **查表（Memoization）的作用**：方法 3 證明了只要加上適當的快取機制，就能將指數級複雜度的程式變成線性級。
3. **實際開發建議**：在實務上，應優先考慮語言內建的次方運算（方法 1）或位元位移 `1 << n`。
